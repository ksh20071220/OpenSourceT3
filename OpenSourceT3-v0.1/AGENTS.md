# AGENTS.md — AI 코딩 도구용 작업 규칙

이 파일은 Codex, Claude 등 AI 코딩 도구가 이 저장소에서 작업할 때 **반드시** 따라야 할 규칙이다.
사람 팀원용 규칙은 `CONTRIBUTING.md`, 모듈 규격은 `docs/INTERFACE.md` 에 있다.

## 1. 프로젝트 요약

캐릭터 이름만 입력하면 웹 검색 + LLM으로 근거 기반 페르소나(JSON)를 만들고, 사용자 API 키로 연결한 LLM에 입혀
대화·학습·상담·실무에 쓰는 C 언어 콘솔 프로그램. 3인 팀 수업 프로젝트(오픈소스).

## 2. 제안서 제약 — 절대 어기지 않는다

다음은 제출한 제안서(`docs/*.docx`)의 내용이므로 바꾸는 코드를 만들지 않는다.

- 언어는 **C (C11)**. 외부 API 통신은 **libcurl + pthread**.
- **로컬 우선**: 페르소나·대화 기록·설정은 사용자 컴퓨터(`data/`)에만 저장. 중앙 서버·원격 저장소·텔레메트리 추가 금지.
- **BYOK**: 사용자가 입력한 API 키로만 LLM 호출. 키를 코드·로그·커밋에 넣지 않는다.
- 페르소나는 **JSON** 으로 저장하고, 대화 때는 **필요한 부분만 골라** 프롬프트에 넣는다 (토큰 절약).
- **모델 라우팅**: 인격 생성·복잡한 추론은 고성능(`TIER_HEAVY`), 일상 대화는 저비용(`TIER_LIGHT`).
- 인격 일관성은 **단순 프롬프트 방식과 비교**해 검증한다 (`ChatRequest.baseline`).
- 라이선스는 GPL v3 예정이므로 GPL v3와 호환되지 않는 라이브러리를 추가하지 않는다.

## 3. 파일 소유권 — 가장 중요

| 담당 | 수정 가능한 파일 |
|---|---|
| 응가 (곽수호) | `src/ui.c` |
| 똥 (오승민) | `src/api.c`, `src/memory.c` |
| 변 (손석현) | `src/persona.c`, `docs/persona-schema.md`, `assets/personas/` |
| 공통 | 그 밖의 모든 파일 (`include/` 전체, `src/main.c`, `src/common.c`, `src/platform.c`, `src/config.c`, `src/purpose.c`, `lib/`, `assets/*.json`, `Makefile`, 문서, 설정) |

규칙:

1. 작업을 시작하기 전에 **누구의 작업인지** 확인한다. 모르면 사용자에게 묻는다.
2. **그 사람의 파일만 수정한다.** 다른 사람의 파일과 공통 파일은 읽기만 한다.
3. 공통 파일 수정이 꼭 필요하면 **수정하지 말고** 사용자에게 "공통 파일 변경이 필요하다"고 알리고 이유와 변경안을 제시한다.
   사용자가 "공통 파일 PR로 진행하라"고 **명시적으로** 지시한 경우에만 수정한다. 그때도 모듈 작업과 섞지 않는다.
4. 헤더(`include/*.h`)의 함수 모양을 바꾸지 않는다. 다른 모듈 기능은 헤더에 선언된 함수로만 쓴다.
5. 다른 모듈이 더미여도 그대로 둔다. 대신 고치거나 우회 구현을 만들지 않는다.

## 4. 코드 규칙

- 모든 공개 함수는 `ErrCode`(int) 반환, 결과는 마지막 출력 인자. 결과를 돌려주는 쪽이 할당, 받는 쪽이 해제.
- **운영체제별 코드를 모듈 파일에 쓰지 않는다.** `<windows.h>`, `<unistd.h>`, `<dirent.h>`, `strdup`, `fopen` 대신
  `platform.h` 의 `platform_*`, `ost3_strdup` 을 쓴다. 경로 구분자는 `/`. 문자열은 UTF-8.
- JSON은 `lib/cjson` 의 cJSON 사용.
- 들여쓰기 공백 4칸, C11, 경고 없는 코드 (`-Wall -Wextra -Wpedantic -Wshadow -Wstrict-prototypes`).
- 모듈 안에서만 쓰는 것은 `static`. 남은 일은 `TODO(이름):` 주석.
- 주석은 한국어. 팀원 모두 C·오픈소스 초보이므로 **왜 그렇게 했는지** 짧게 설명을 단다.
- 메모리 누수를 남기지 않는다 (해제 경로를 오류 분기까지 확인).

## 5. 빌드와 확인

```bash
make check     # 경고를 오류로 취급한 빌드 + ./build/opensourcet3 --selftest
```

- 작업을 마치기 전에 **반드시 `make check` 를 통과**시킨다.
- CI(GitHub Actions)가 Windows(MSYS2 UCRT64)와 Linux에서 같은 검사를 한다. 한쪽에서만 되는 코드를 만들지 않는다.
- `--selftest` 는 모든 모듈을 차례로 부른다. 실제 구현이 들어와도 **API 키 없이** 통과하거나 SKIP 되어야 한다
  (키가 없으면 네트워크 호출 전에 `ERR_INVALID_ARG` 또는 `ERR_API` 반환).

## 6. 하지 말 것

- `data/` 폴더, API 키, 실제 대화 기록을 커밋하지 않는다.
- 저작권이 있는 작품 속 캐릭터의 설정·대사를 `assets/` 에 넣지 않는다 (샘플은 자체 창작만).
- 안전 지시문(`api.c` 의 `SAFETY_PROMPT`)을 약화하거나 사용자가 끌 수 있게 만들지 않는다.
- 새 외부 라이브러리를 팀 합의(공통 PR) 없이 추가하지 않는다.
- 커밋 메시지는 `[영역] 내용` 형식 (`CONTRIBUTING.md` 5장).
