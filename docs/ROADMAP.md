# 로드맵

> 제안서 5장: "초기 구현은 캐릭터 정보 수집, 행동 증거, 인격 추출, JSON 대화에 집중하고,
> 개발이 진행됨에 따라 자동 OOC 보정 및 고급 업무 도구 연동 기능도 구현하는 방향으로 확장"

## 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 0. 뼈대 | 공통 파일, 규격(헤더), 더미 구현, 빌드·CI, 협업 문서 | ✅ v0.1 |
| 1. 각자 핵심 구현 | 아래 담당별 1차 목표 | ⬜ |
| 2. 연결 | 더미를 실제 구현으로 바꾼 모듈끼리 실제 API 키로 전체 흐름 확인 | ⬜ |
| 3. 검증 | 단순 프롬프트 방식과 비교한 인격 일관성(OOC 비율) 측정 | ⬜ |
| 4. 확장 | 자동 OOC 보정, 실용 업무 도구, 외부 도구 | ⬜ |

## 담당별 1차 목표

**곽수호 (`ui.c`)**
- [ ] 목적 선택 화면을 분류(학습·실무·상담·대화)별로
- [ ] 대화 화면: 이전 대화 다시 보기, 명령어 도움말
- [ ] 새 캐릭터 만들기 후 바로 대화로 이동
- [ ] 설정 메뉴 (모델·회사 변경, 캐릭터 삭제)

**오승민 (`api.c`, `memory.c`)**
- [ ] OpenAI 호환 요청 JSON 만들기 → libcurl로 보내기 → 응답에서 답변 꺼내기
- [ ] 스트리밍(`"stream": true`) 응답을 조각으로 `on_chunk` 에 전달
- [ ] HTTP 오류 → `ErrCode` 변환, 모델 거절 응답 처리
- [ ] 대화 기록을 `data/history/` 파일에 저장·불러오기
- [ ] 검색 API 연동 (`api_search`)

**손석현 (`persona.c`)**
- [ ] 스키마 확정 (`docs/persona-schema.md` 검토 제안 결정)
- [ ] 검색 결과 → 근거 추출 → 신뢰도 평가
- [ ] 고성능 모델로 인격 추론 → JSON 생성 → `persona_validate` 로 검증
- [ ] `persona_build_prompt`: 입력·목적에 맞는 항목만 고르기

## 제안서 그림 2 항목별 담당

| 그림 2 항목 | 담당 | 위치 |
|---|---|---|
| 사용자 입력 (이름, 추가 키워드, 실무 요청, 결과 확인·수정) | 곽수호 | `ui.c` |
| 웹 검색 | 오승민 | `api_search` |
| 자료 정제·필터링 (신뢰도 평가, 중복 제거) | 손석현 | `persona_create` |
| 인격 정보 추출, 페르소나 구조화 | 손석현 | `persona_create`, `persona_build_prompt` |
| 로컬 저장소: 페르소나 파일 | 손석현 | `data/personas/` |
| 로컬 저장소: 대화 기록 | 오승민 | `data/history/` |
| 로컬 저장소: 참고 자료 캐시 | 손석현 | `data/cache/` (후순위) |
| 사용자 입력 처리 (의도·대화/실무 분류) | 공통 + 곽수호 | 목적 선택 (`purposes.json`) |
| 모델 라우팅 | 오승민 | `api_chat` (목적의 `tier`) |
| LLM API 연동 (스트리밍, 모델별 파라미터) | 오승민 | `api.c`, `AppConfig.temperature` |
| 출력 후처리 (형식 정리, 안전성 필터링, 출처 표시) | 오승민 | `api.c` |
| 대화 기록 및 기억 관리 (요약·장기 기억) | 오승민 | `memory.c` |
| 실용 업무 지원 | 공통 | 1차는 목적 지시문으로 대응, 도구 연동은 4단계 |
| 외부 도구 (RAG, 코드 실행, 일정 등) | **미정** | 4단계 |
| 인격 일관성 검증 (단순 프롬프트와 비교) | **미정** | 3단계. 비교용 모드(`baseline`)는 준비됨 |
